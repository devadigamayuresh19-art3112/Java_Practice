Create a modern, responsive web application named “FirstAid”.

FirstAid is a citizen-reporting and road-damage prioritization platform. Citizens can upload or capture photos of potholes, add their location, provide a short description, and submit a report. The system analyzes the image using computer vision, detects potholes, estimates their severity, merges duplicate reports from nearby locations, and assigns a priority score for maintenance teams.

Build the website as a polished hackathon-ready prototype with a clean, accessible, mobile-first design.

Branding:
- Website name: FirstAid
- Tagline: “Report. Prioritize. Repair.”
- Use a professional civic-tech visual style.
- Primary colors: deep navy, safety orange, white, and light gray.
- Use orange or red only for urgent and high-priority alerts.
- Add a simple shield or road icon beside the FirstAid logo.
- Use rounded cards, subtle shadows, clear typography, and large touch-friendly buttons.
- Use Lucide icons or another modern icon library.
- Add smooth hover effects and subtle page transitions.

Technology:
- Use React with TypeScript.
- Use Tailwind CSS.
- Use reusable components.
- Use React Router for navigation.
- Use Leaflet with OpenStreetMap for maps.
- Use mock data and local state if no backend is available.
- Structure the code so that a FastAPI or Node.js backend can be connected later.
- Make the interface fully responsive for mobile, tablet, and desktop.
- Include loading, empty, error, and success states.

Optional AI Detection Prompt

Add a computer-vision analysis module to the FirstAid application.

When a citizen uploads a road image:
1. Send the image to a configurable detection API.
2. Show an “Analyzing image…” loading state.
3. Receive detected object bounding boxes and confidence values.
4. Display the bounding boxes over the uploaded image.
5. Classify the damage as Small, Medium, or Large based on bounding-box area.
6. Calculate a severity value from the detection confidence and estimated size.
7. If confidence is below 0.60, mark the report as “Requires Manual Review”.
8. If the API is unavailable, use realistic mock analysis data so the demo still works.
9. Keep the API URL in an environment variable named `VITE_DETECTION_API_URL`.
10. Add clear error handling and never block report submission permanently if the detection service fails.
